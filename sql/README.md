# SQL Terminal

A static, English-language SQLite playground with the same dark styling as Python Terminal. No build step or backend is needed.

From the repository root:

```sh
python3 -m http.server 8000
```

Open http://localhost:8000/sql/ (or `/learn/sql/` on GitHub Pages). Use HTTP or HTTPS rather than opening `index.html` directly.

- **Table tabs**: each table has its own tab; Query is always the last tab. New table is available on the same row as the tabs. When there are no tables, only the Query tab is shown. New table opens the creation dialog, which can be cancelled.
- **Tables**: create tables, choose primary keys and required fields, view saved rows as read-only text. Click a row (or focus it and press Enter) to edit that row. Clicking another row ends the previous row’s edit mode while keeping its unsaved changes; Escape returns the current row to read-only mode. One blank row appears below existing data. Fill them in and click Save to insert new rows, or edit existing cells and click Save to update them. Add row adds another blank row; Reset discards the current table’s unsaved edits. NULL is separate from empty text. Leave Auto selected for generated IDs. Each Save runs in a transaction, so an error preserves all edits and saves none of that batch. Untouched blank rows are ignored, and untouched fields use their database defaults. Unsaved edits remain when switching tabs; save or reset them before running SQL or editing that table’s structure. Unfinished grid edits are saved separately in localStorage as you type and restored after reloading or reopening the browser. They remain pending until Save; Reset discards them. Field types: INTEGER (whole number), REAL (decimal), VARCHAR(n), TEXT, DATE, BOOLEAN. VARCHAR length is enforced with a CHECK constraint. Allow NULL controls whether a value is optional. Primary keys are non-null; Auto increment is available for one INTEGER primary key and prevents automatic reuse of deleted IDs. The default id field has Auto increment enabled. Click Data types in the lower-left of the structure dialog for examples and a brief guide. Dates use `YYYY-MM-DD`; booleans store `0` or `1`. SQLite uses flexible type affinity, so SQL queries can insert other value types.
- **Primary and unique keys**: in New table or Edit, select several Primary key checkboxes to create a composite primary key. Auto increment is only available for a single INTEGER primary key. Constrains unique creates a group of one or more selected fields; multiple groups can be added or removed. Existing simple UNIQUE constraints and unique indexes are loaded into the editor. Partial/expression indexes remain managed in Query. Duplicate values, NULL primary-key values, or broken foreign-key references reject the edit and roll back the entire change. UNIQUE groups allow NULL values under SQLite rules.
- **Column order**: drag the handle at the start of a field row, or focus it and press Arrow Up / Down. New tables use this as their SQL column order. For existing tables, this changes the data grid and structure editor order, saved locally; SQL column order (including `SELECT *`) remains unchanged.
- **Database menu**: the hamburger icon before New table opens Generate Data, Backup, Restore, and Delete database. Generate Data and Backup appear only when at least one table exists. Delete database requires confirmation and clears all tables and pending grid edits while retaining Query text.
- **Generate Data**: in the database menu, before Backup, choose 0–10,000 rows to add for each table (0 skips a table). Foreign-key dependencies determine parent-first generation order. Related fields such as student_name are copied from the chosen parent record where their names identify that relationship. Adds sample values based on field types, column names, and table names. Recognized English/Vietnamese names produce Vietnamese person names, matching example.com emails, phone numbers, addresses, cities, school ages/classes, scores, subjects, prices, and quantities. Ages and birth dates agree. Unknown columns use generic records; this is a local rule-based generator, not an AI service. Generated IDs are automatic; primary/unique keys and foreign keys are enforced. Referenced parent data is reused, including composite foreign keys and many-to-many links. Required circular relationships need seed data; the generator reports unsupported empty cycles. Save/reset pending edits first. Generation runs in a worker; Cancel/Escape discards the run. All requested rows are committed and saved together, or none are added if constraints prevent completion. Arbitrary CHECK constraints or exhausted unique values may make generation impossible.
- **Backup**: downloads a timestamped `.sql` file containing all saved tables and rows, indexes, views, triggers, and automatic-ID counters. Save or reset unfinished edits first. Restore into an empty SQLite database. Virtual tables are not supported by this exporter.
- **Restore**: choose a `.sql` file using Restore next to Backup. If tables exist, confirm replacement of all saved data and unfinished edits. SQL runs in a temporary database in a worker; invalid SQL or foreign keys leave the current database intact. Stop cancels a long restore. Successful restores are saved locally, preserve the Query editor text, and clear old grid drafts and column-order preferences.
- **Delete selected**: select saved rows using the leading checkboxes, then confirm Delete selected. The header checkbox selects the displayed rows (up to 500), not unseen rows. Selected rows are removed in one transaction using their original row identifiers; constraint failures roll back the whole deletion. Other unfinished edits must be saved or reset first.
- **Delete table**: delete the current table and its data after confirmation. Foreign-key rules are enforced; a failed deletion leaves the database unchanged. Deleting the last table returns to Query.
- **Edit structure**: rename tables and columns, add columns, or remove columns with confirmation. Allow NULL is editable for existing non-primary-key columns. Switching it off fails without changing the table if any existing values are NULL. These changes rebuild the table in a transaction while preserving its data, indexes, triggers, defaults, foreign keys, and automatic ID sequence. Existing column types remain read-only. Primary-key and Auto increment settings are editable. SQLite rejects operations that violate primary keys, indexes, or other dependencies. Structure edits run in a transaction and roll back on error. New required columns cannot be added to populated tables without a default; add optional columns first or use SQL.
- **Query**: execute one or more SQL statements using Run or Ctrl/⌘ + Enter. Results are shown separately. Stop terminates the worker and discards all changes from that run. A SQL error preserves earlier completed statements; use an explicit `BEGIN; … COMMIT;` for atomic changes. Complete transactions within the same run.
- Database, unfinished grid edits, and query text are saved in localStorage for the current browser and origin. Storage failures are reported; private browsing or clearing browser data may remove saved work. Keep important data backed up separately.
- Table grids load up to 500 saved rows; query results display up to 1,000 rows per statement. Use `ORDER BY` for predictable order. Query execution runs in a Web Worker to keep Stop and the interface responsive.

SQLite is supplied by the vendored [sql.js](https://github.com/sql-js/sql.js) 1.13.0 runtime. All runtime assets are local; no CDN or network connection is needed once served. Its license is in `vendor/LICENSE`.
